# Jardins — сайт піцерії (Полтава)

Статичний сайт без збірки (HTML + CSS + JS) і серверна функція приймання замовлень.
Мова сайту — українська.

## Структура

```
index.html            розмітка, SEO, структуровані дані (Schema.org Restaurant)
css/styles.css        стилі та кольори (змінні на початку файлу)
js/config.js          телефон, адреса, графік, соцмережі, карта, endpoint замовлень
js/menu-data.js       МЕНЮ І ЦІНИ — єдине джерело даних (для сайту і для сервера)
js/art.js             демонстраційні ілюстрації та іконки
js/app.js             меню, кошик, форма, анімації
lib/order-core.js     перевірка замовлення, антиспам, відправка в Telegram / webhook
api/order.js          функція для Vercel  (POST /api/order)
netlify/functions/    функція для Netlify (/api/order через netlify.toml)
images/               сюди кладуться реальні фото
```

## Локальний перегляд

Відкрийте `index.html` у браузері або запустіть `npx serve .`.
Без налаштованого сервера форма покаже помилку або демо-режим — успіх не показується, якщо замовлення не надіслано.

## Що заповнити перед запуском

1. **Меню** — `js/menu-data.js`: `price` (число в грн), `weight`, `size`, `description` для кожної страви.
   Поки `price: null`, на сайті написано «Ціну уточнюйте», а склад — «Склад уточнюйте у закладі».
2. **Графік роботи** — `js/config.js` → `hours`. Поки `null`, показується «уточнюйте за телефоном».
3. **Соцмережі** — `js/config.js` → `social`. Порожні поля не відображаються.
4. **Умови доставки** — `js/config.js` → `deliveryNote` (вартість, зона, час). Порожнє — блок прихований.
5. **Точка на карті** — відкрийте заклад у Google Maps, перевірте мітку й впишіть `maps.lat` / `maps.lng`
   (за бажанням `maps.placeUrl` і `maps.reviewsUrl`). Без координат карта шукає за адресою.
6. **Фото** — покладіть файли в `images/` і вкажіть їх у `menu-data.js` (`image`) та `config.js` (`images`).
   Поки фото немає, показуються демонстраційні ілюстрації, які не відображають реальний вигляд страв.
7. **SEO** — у `index.html` додайте `url`, `openingHours`, `sameAs` до блоку JSON-LD, коли будуть дані.

## Приймання замовлень (Telegram / CRM)

Замовлення йдуть на `POST /api/order`. Сервер сам перераховує суму за `menu-data.js`,
перевіряє поля, відсікає спам (приховане поле, мінімальний час заповнення, ліміт спроб з однієї адреси)
і відправляє замовлення в Telegram та/або на webhook CRM.

**Vercel:** імпортуйте проєкт, у Settings → Environment Variables додайте змінні, зробіть Redeploy.
**Netlify:** змінні в Site settings → Environment variables; `netlify.toml` вже пов'язує `/api/order` з функцією.

| Змінна | Призначення |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен бота від @BotFather |
| `TELEGRAM_CHAT_ID` | id чату або групи, куди приходять замовлення |
| `ORDER_WEBHOOK_URL` | (необов'язково) CRM або інший сервіс, отримує JSON замовлення |
| `ORDER_WEBHOOK_TOKEN` | (необов'язково) надсилається як `Authorization: Bearer …` |
| `ALLOWED_ORIGIN` | (необов'язково) домен сайту, напр. `https://jardins.example` |

Токени зберігаються тільки на сервері, у клієнтський код вони не потрапляють.

Режими роботи форми:
- сервер налаштований і доставив замовлення — гість бачить підтвердження з номером;
- змінні не задані (відповідь 503) або `orderEndpoint: ''` — **демо-режим**, сайт прямо повідомляє, що замовлення не надіслано, і пропонує зателефонувати;
- збій мережі чи сервера — повідомлення про помилку з номером телефону, кошик зберігається.

Перевірити після запуску: оформіть тестове замовлення і переконайтеся, що воно прийшло в Telegram.
